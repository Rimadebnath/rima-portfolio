LMS Manager Portal

frictionless approval dashboard designed to make team leave management fast, fair, and contextual.

Duration

2 Weeks (2026)

Context

Enterprise SaaS UX

Role

Product Designer & Developer

Methods

User Flow, Prototyping

The Problem Space

Before the introduction of this approval workspace, managers managed leave requests through a fragmented set of communication channels (Slack threads, calendar invites, emails, and verbal requests). This fragmentation introduced substantial cognitive friction, leading to several systematic workflow breakdowns:

Forgetting to Reply

Requests lay dormant in messaging threads. Without a central request portal, managers simply forgot to respond, leaving team members in scheduling limbo for days.

Team Availability Blindness

Managers authorized leaves in isolation. Without a unified view of team absences, they frequently approved overlapping requests, causing severe understaffing during critical weeks.

Chasing Balance Information

Confirming whether an employee had sufficient remaining leave days required checking a separate HR database. This added friction meant balance checks were often skipped entirely.

No Audit Records

Decisions lacked systemized records. Verbal approvals and last-minute changes created disputes, reporting misalignment, and extra cleanup overhead for HR departments.

User Flow & System Topology

To address these gaps, we designed a unified decision loop. Below is the system topology, adapted to the portfolio's clean brutalist style. It details how edge cases (overdue periods, overlaps, and zero balances) are assessed in parallel prior to the manager reaching a decision node, returning the user back to the primary workspace queue.

Dashboard Topology: The 3 Zones

To address the identified breakdowns, the manager portal was divided into exactly three distinct functional zones. This topology minimizes visual noise and focuses the manager on the core tasks.

Zone 1: Quick Stats (3 Tiles)

  • Pending Requests Tile: The primary queue trigger. Tracks how many decisions require attention today.
  • On Leave Today Tile: Immediate context. Clicking this card reveals a list detailing which team members are currently absent.
  • Overdue Tile: Risk flag. Signals if a request has sat longer than 48 hours without action.

Zone 2 & 3: Context & Availability

  • Zone 2 (Pending Queue): Contains inline search and key filters. Displays the request rows along with clear, color-coded warning badges.
  • Zone 3 (Right Sidebar - Weekly Summary): Aggregates approved leaves for the upcoming week. This sidebar gives managers instant team capacity context before approving another leave.

Key Rationale & Design Learnings

Building the leave management dashboard surfaced a core product design principle: context is key to confidence.

Instead of building an administrative table loaded with history metrics and irrelevant data points (like full accrual accounts or request logs), the design focuses entirely on decision-influencing edge cases. Highlighting team conflicts, overdue actions, and unpaid balances directly in parallel ensures managers can make quick decisions with full context, avoiding calendar conflicts or accidental policy violations.
